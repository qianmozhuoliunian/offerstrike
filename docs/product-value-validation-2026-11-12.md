## 结论

**基础流程可用，但尚未验证出优于成熟工具的独立产品价值。** 当前最值得保留的是来源题、连续作答、记录保存和有理由的自评复习；最需优先解决的是搜索内容质量与初学者教学体验。现在不宜继续以功能数量扩张范围。

这是代理执行的产品质量检查，不是真人用户研究；未招募用户、未测留存、学习提升或付费意愿，未运行竞品做等条件计时。不能声称省时比例、用户偏好或竞品更差。

- 使用项目已配置的真实搜索和 AI 服务；发送固定测试岗位、公开搜索标题摘要和人工编写的虚构回答。
- 服务在独立工作目录与端口 19516 运行，未读取或改写用户在 19002 使用的数据库；验证结束后停止隔离服务和专用无界面浏览器。
- 四次 API 搜索：AI 应用开发工程师（近一年、不限时间）、前端开发工程师（近一年）、产品经理（近一年）；另在真实浏览器执行一次前端近一年搜索。
- 先检查相关结果能否提供原帖线索，再回查 11 个公开 URL。自动页面读取取得 5 个可读正文/列表页、3 个仅导航壳、3 个读取失败。该比例只描述这次工具读取，不代表普通浏览器或平台长期可访问率。

| 岗位 / 时间 | 主列表：AI 认为可能相关 | 无法判断 | AI 认为可能无关 | 耗时 |
| --- | ---: | ---: | ---: | ---: |

浏览器再次搜索前端近一年时，主列表变为 16 条。搜索返回与模型判断均可能变化，本轮未固定同一上游响应反复评估，因此不能把差异归因于某一个环节。AI 岗位两次检索改变了服务端搜索条件，也不能将 3→23 全部解释为本地日期过滤造成。

### 已核实的问题

1. **内容类型混在主列表。** AI 岗位近一年第一条是[多篇面经整理](https://www.nowcoder.com/discuss/877151327091027968)，正文明确为多篇内容的集合；前端结果中的 [SegmentFault 文章](https://segmentfault.com/a/1190000048059338) 是趋势分析，不能当作作者单次面试自述。这些内容可能有参考价值，但当前搜索卡片没有内容类型分类，用户仍需逐条辨认。
2. **聚合页没有落到具体帖子。** 产品经理主列表含[快手公司面经页](https://www.nowcoder.com/enterprise/898/interview)及微众银行公司面经 URL。快手页面回查确实是混合职位的列表。把列表页作为结果意味着用户还要再找一次目标原帖，其索引日期也不能代表列表内每场面试的日期。
3. **摘要不能可靠代表正文。** 已读的 Agent 整理页包含正文后的相关推荐，搜索摘要也混入了推荐内容。产品经理结果里有标题为 PE/全栈的帖子，AI 的岗位依据却来自摘要中的产品经理字段；该帖本次未能读到正文，故只标为疑似摘要污染，不能下结论说正文一定无关。
4. **时间依据需继续核对。** [拼多多 Agent 题目讲解页](https://www.nowcoder.com/discuss/919634965879324672)的标题日期为 08-16，页面显示 08-19，而搜索返回 2026-11-03。具体发布时间、编辑时间与检索服务日期之间关系尚未核实。当前 UI 已写“日期参考”，但日期筛选仍可能误导希望获取近期面试经历的用户。

### 能成立的正面结果

前端首条[字节社招原帖](https://juejin.cn/post/7571657746346950710)可读，含作者自述时间线和具体问题，显示日期与搜索返回一致；可回查一道关于 `this` 的问题进入练习。作者自述并不等于独立证实其经历。

四次采样共出现牛客、掘金、知乎、CSDN、博客园、SegmentFault 六类候选；未出现 51CTO，不代表该平台不支持或没有内容。本次没有逐平台单独搜索，也未完成全部来源覆盖率评估。

## 2. AI 陪练：能纠错，但教学质量不稳定

固定题目：RAG 已召回相关文档，答案仍出现无依据结论时，如何定位和改进？

| 人工样本 | 实际结果 | 判断 |
| --- | --- | --- |
| 明说不会且不理解 RAG | 给出检索、上下文、生成的框架并追问基本流程；同时要求不会的用户展示完整排查思路 | 有帮助，但信息密度偏高，仍偏面试评价，未充分降低难度 |
| 声称温度 0 完全消除幻觉、相似度高保证正确 | 明确指出两项断言不成立，要求检查答案与证据 | 本样本纠错有效；不能外推全部技术题准确性 |
| 已说明分环节评测、引用校验、拒答和人工抽检 | 肯定已提及内容，再追问落地方式 | 基本针对回答；部分“待补充”与已有回答重叠，可能让用户反复扩写 |

三次点评分别约 2.2、3.0、2.2 秒，总结约 1.2、1.8、1.8 秒。只测一种技术主题，未覆盖产品案例、经历题、不同模型或长期稳定性。

浏览器里第二轮明确请求先给简单例子，AI 确实给了 `this` 的示例再追问；同时用“知识点尚未建立”推断掌握程度，语气和结论强度仍值得调整。应区分“本轮未展示能力”和“用户不会”，也应区分练习教学与正式面试。

## 3. 复习：自评规则有效，回答内容尚未驱动下次推荐

- 浏览器：从已确认来源题开始，两轮作答、总结、选择“需要再练”、刷新恢复均成功；未捕获 JavaScript 异常。390px 视口文档宽度仍为 390px，这只验证该页面没有横向溢出，不等于完整无障碍验收。
- 自评后 API 返回“你标记为需要再练”，建议间隔 1 天。将时间移到次日的隔离纯函数验证中，该题成为到期推荐；今天则优先未练题。
- 反事实检查：固定题库、时间和自评，将回答/反馈分别替换为明显错误与完整正确，推荐完全相同。
- 原因：`src/workspace.js` 的推荐查询不读取答案和反馈；`src/recommendation.js` 按练习记录和显式自评排序，间隔为需要再练 1 天、未自评 3 天、比较熟悉 7 天。

**因此当前可描述为“基于自评和练习记录的间隔复习”，不能描述为“已经根据 AI 识别的薄弱点个性化安排”。** 保留用户自评是合理选择；若将来引入 AI 推断，需要展示依据、允许纠正，并验证推荐确实更有效。

## 4. 输入与失败处理

真实服务可用时，“科比”被拒绝，纯数字被本地规则拒绝，“增长黑客”被接受。第一次沙箱网络受限试跑中，语义判断降级为需确认，包括“科比”；这是既有“无法判断则确认”策略，不是纯本地语义识别。重新在允许访问网络的执行环境中验证后得到上述真实结果，没有将沙箱失败算作线上服务故障。

## 5. 竞品比较与下一步建议

见[竞品源码核对](validation-competitor-2026-11-12.md)：InterviewGuide 已有较完整的面试和知识库能力，InterviewRadar 已有来源与证据校验。不能以来源追溯、AI 追问或页面完整作为独占优势。本次未运行竞品，因此没有完成用户耗时或效果的对照试验。

建议先验证三个改进方向，**尚非已授权的新功能范围**：

1. 先提高原帖质量：把作者自述、整理/题解、列表页分开；检查正文主体与摘要引用的关系；展示少量有用结果。验收不以“返回更多”为目标。
2. 把不会答时的体验做扎实：给一个小例子、让用户试答，再决定追问深度；避免每轮都堆缺点或要求重复已有内容。
3. 将总结中的下一步接到可执行练习，并明确当前仍是自评调度；再验证是否需要 AI 辅助更新练习优先级。

后续真人验证建议（待执行）：3～5 位正在准备同一岗位的用户，使用同样材料，交替体验本项目与习惯工具，记录找到 3 道有出处题目所用时间、剔除/纠正次数、能否独立完成一道练习、次日能否解释并开始推荐题。先获取他们的直接反馈，不以代理模拟代替偏好与留存结论。

本轮结论是**继续聚焦验证，暂不扩大功能**；尚无依据建议直接放弃项目，也无依据称它已有竞争优势。
