# AI 点评固定案例

`tests/fixtures/review-cases.json` 包含四类虚构输入：准确的技术回答、部分回答、无意义输入，以及存在多种合理回答的开放问题。每条包含问题、回答和 `review_criteria` 人工检查要点。它们是回归评估样本，不是真实用户答题记录。

## 自动化检查

`npm test` 使用模拟 AI 服务覆盖这些输入，检查 API 能接收并保存结构合法的点评与追问；模型返回格式错误时，不应写入练习记录。解析器测试还覆盖空内容、缺字段和过长内容。

模拟服务中的 `mock_response` 是测试数据，不是模型的真实输出。因此，测试通过只能说明接口、存储和格式处理符合测试预期，**不能说明真实模型理解正确、没有编造，或点评质量可靠**。

## 人工复核真实模型

需要评估模型时，在独立测试数据环境中逐条提交固定案例，并记录模型名称、时间、输入和完整输出。按每条的 `review_criteria` 判断“通过 / 不通过 / 无法判断”，记录具体证据；可以多次运行观察是否稳定。特别注意：

- 对无意义输入，不能编造作答优点或认为用户一定不会。
- 对开放问题，合理答案可能不止一种，不能因为与示例措辞不同就判错。
- 用户回答与模型引用的内容不一致时，应记录为待核查；不要只依据输出是有效 JSON 就认为点评正确。

真实模型测试会产生外部调用与可能的费用。不要使用真实简历、私人回答或密钥作为评估案例，也不要将真实用户记录混入固定样本。
