# 规格：真实业务质量评估

## 固定输入

- 产品基线为 `18e8b24a9f816c95a541498249dff31aeeea1f5a`。评估脚本与数据独立于产品逻辑。
- 20 组岗位、时间和来源组合，预先写明题目、合成答卷、预期正误与可接受的追问。按实务场景编写，既有历史上可定位的公开面经，也有证据未知的搜索任务。合成答卷不用于证明真实用户的学习效果。
- 深度研究以当前 Node 阅读能力运行，用 Tavily Basic 和官方 DeepSeek。一个场景最多一次有预算的 Research，两次固定的岗位与练习处理分别在隔离库中运行，不能互相借用题库覆盖。四组固定纠正回答用于比较 Career 前后建议。

## 计分规则

- **发现覆盖率**分别给出有供应商命中、产品保留至少一条线索、有候选、有可确认候选的场景数除以 20。这是样本覆盖率。整个公开网络的相关帖子总数未知，无法计算全网召回率。
- **阅读**以读取工具调用为分母，分别记成功读取正文、已发提取、可接受输出。零尝试的场景按入口因素列出，不能归到读取成功。
- **证据与题目**对每条候选打开原帖核对摘录、提问性质、来源和主题。公司明确时区分已证实、错误、不明、系统未声称；不明确时不计入指定公司准确率。截断、登录不可读、归属不明均不能按正确计。
- **点评与追问**先根据预先写好的技术判断标准核查点评，再复核结构化观察。判断正确、错误和漏答为三个类。证据按本轮答案逐字检查；遗漏还须引用问题的明确要求。追问按有实际追问的回答计相关率，另报告有缺口却未追问的数量。正确答卷可以没有追问。
- **Career**缺题时检查任务主题是否受岗位和历史支持、是否需要用户确认。四组更正以原题与新作答的证据为准，检查待补练是否降低或转向。仅因变成另一条追问，不能算错误已消除。
- **闭环**严格口径从各自任务开始到经核对入库、成功保存评价、Career 给出可追溯的新建议。分别报 20 组端到端通过数和可确认后继续的成功数。源站人工等待不混入服务端接口用时。
- **延迟与成本**保留每条外部请求 HTTP 状态、耗时和返回的用量。费用使用同一公开价口径估算，区分 Tavily credits、DeepSeek token、费用估计和未取得的账单。缺失用量不记零。

## 数据与对照

- Golden Dataset 由可人工核对的预设题目、合成答卷及标准组成。结果逐条对照规则，不使用额外 LLM 判分。单人复核结论须能从原文重做，独立人工复标及一致性评估另记。
- InterviewRadar 固定公开提交，比较源码和示例可验证的能力。对照未运行等价 20 组，不能排序两个产品的实际效果。
- Mock 回归仅验证故障、批处理规则与存储接口。真实上游结果单独保存和引用。
