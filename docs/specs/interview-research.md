# 规格：有上限的多源面经检索

- 状态：已完成（多源接入）；真实效果待验证
- 最后更新：2026-11-13

## 问题与目标

当前应用内搜索固定调用 Tavily。它不可用或返回的相关面经线索太少时，求职者只能重试或手动找帖。先让面经检索可以切换服务并解释检索过程，验证它是否值得发展成独立研究 Agent。

## 范围与验收

- 沿用现有搜索页和 `POST /api/search`。有 Tavily 时先并行跑现有两路查询；若两路均失败，或通过域名、日期、岗位和内容类型初筛后少于 3 条去重面经线索，且已配置 Exa，才补搜一次。仅配置 Exa 也可独立搜索；未配置任何服务时提示手动添加来源。一次搜索最多发起 3 次检索请求；单次请求（含解析响应）最多 12 秒。
- 补搜保留目标岗位、公司、平台和时间要求，结果合并去重后再做可选的 AI 相关性判断。补搜门槛是初筛策略，3 条不代表有 3 篇已核实的真实面经。
- 返回搜索服务、补搜原因、请求次数及检索耗时。单个请求失败时保留成功的结果并提示；全部失败时明确报错。结果仍区分面经线索、补充内容和待核实，不将摘要当作可入库证据。
- 用模拟服务覆盖提前停止、结果偏少、服务故障、仅备用服务、跨服务去重、严格筛选、隐私与失败提示。用固定岗位任务对比真实搜索质量，缺少凭据时记录未验收。

## 数据与外部服务影响

搜索只向已配置且本次启用的服务发送目标岗位、公司关键词、检索词、平台与时间条件；不读取或发送 JD、简历、作答和历史记录。Exa 使用其估算的发布日期；两家返回的日期都需要回原帖核对。不改变 SQLite、题目确认或备份。

## 后续范围

本次实现规则驱动的检索模块。自动阅读原帖、基于证据提题、按弱项安排再研究与独立求职备战 Agent，待分别验证数据访问、检索质量和复习价值后再决定。

## 验证记录

- 2026-11-13：模拟服务覆盖补搜、提前停止、两家全部失败、Exa 独立运行、域名和日期过滤、去重以及不发送 JD 或简历。既有 API 和页面逻辑测试继续覆盖搜索、AI 初筛、来源和题目保存。
- Tavily 实测一次「前端开发实习生 / 牛客 / 近一年」：两路中一路失败，耗时约 12 秒；0 条通过初筛，11 条待核实，未核对这些原帖。项目未配置 Exa 密钥，未验证真实补搜效果。对照任务见[面经研究路线](../interview-research-roadmap.md)。
