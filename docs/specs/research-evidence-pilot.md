## 目标与范围

在深度研究中验证一条单站链路，从公开关键词到可人工核对的候选题。首批处理博客园已核对使用范围的文章。显式选择博客园且服务器配置试点文章后启用。沿用 Node 正文读取、模型预算、人工确认、SQLite 和 v1 备份。配置 Python 时，深度研究复用本机 FastAPI 检索和超时处理。

从 InterviewRadar [`f551c9c24`](https://github.com/KunChen1110/InterviewRadar/commit/f551c9c24e274c4a361e870f5e269ddb7cef6ca6) 借鉴原文锚定和分阶段核验。试点使用项目现有依赖和自有实现。跨站读取、跨帖语义合并、转载识别和高频排序另行验证。

### 公司归属修复与复验

`23bf277` 的试点校验依赖摘录完整命中和公司名子串，因而在「不是远帆科技」上给出了错误归属。修复后区分肯定归属、否定归属、仅提及和无法判断。带公司筛选时，同段或本节标题须提供明确的肯定归属。本节或文章导语中的明确否定和第三方来源标记会阻止候选通过。明确否定优先于截短的模型摘录。评论区仍由正文读取器排除，保存题目仍需用户确认。

### 跨段落与轮次证据复验

`bfbf7f7` 只接受题目所在段落和最近的正文标题。它会漏掉同一节开头的明确自述、上一级公司章节给下属轮次划定的范围，以及只写在原帖标题中的岗位。试点继续要求题目和作者亲历的证据位于本节正文。仅在轮次标题无公司信息且有明确的上级公司章节时，才继承父级标题。同节首段须明确表述作者参加了目标公司的面试，才可在无分节边界时关联后续题。否定、另行声明公司、第三方来源和可识别的纯文本分节会阻断继承。原帖标题仅在正文已经确立公司、且标题也指向该家公司时补充岗位证据，界面标明岗位证据来自原帖标题。

引入来源为原帖 HTML 的标题与正文标题层级。模型请求最多额外包含 300 个字符的原帖标题和正文标题层级，正文范围仍受 6000 字符限制。题干证据的原文范围与人工确认入库流程沿用现有实现。
