# 规格：复用牛客正文读取

- 状态：已完成

将 InterviewRadar 的 MIT 牛客正文选择器与时间解析移植到现有 Node 读取器，保留上游声明。复用搜索结果和 Research 工具预算，候选依旧需要逐字证据及人工确认。仅识别公开牛客讨论文章，正文缺失时失败并保留原帖链接。标题与正文分开，避免导航、评论及相关帖子进入证据。

当前单用户工作台和 SQLite 沿用原接口。验证 URL 边界、标题正文选择器、独立的发帖日期和空页面处理，再用真实牛客页面和 DeepSeek 运行一组提取。无关模块沿用既有回归。

## 实现

HTML 讨论页实测会返回约5.7KB空壳。牛客公开内容详情响应能按文章ID返回正文与独立的 createTime，因此选择固定公开详情地址读取，同一操作只发出一次请求。正文、标题和时间分离的处理方式及日期换算参考 InterviewRadar 的 MIT connector，版权声明在 THIRD_PARTY_NOTICES.md。文章ID必须与请求一致，空正文、异常状态或身份不符均失败。只处理数字 discuss 原帖，相关帖子和评论不进入正文。

FEMentor 的公开 README 标明 Private。interview-question-search 声明部分上游未提供许可证。这次复用选择的是有明确 MIT 授权的 InterviewRadar 思路及相应声明，具体的公开详情响应适配由本项目实现。

## 验证

真实 Tavily、牛客正文与 DeepSeek 跑通一组「AI Agent 开发工程师 / 字节跳动 / 缓存」。1次搜索、1次读取、1次模型提取，约10.17秒，得到1条「手撕：实现 LRU 缓存」，再次读取原文可逐字定位。原帖为多场面经整理，因此仅作为待核对候选，未自动认定为作者亲历或写入用户题库。单独复查时出现过一次9秒超时，低频重试成功。

模块测试验证来源ID绑定、日期、空响应、评论排除、固定主机和既有候选人工确认入库与幂等。真实原帖的发布元数据为2026-09-18，文内描述的面试时间为2026-09-17，两者分别保留。此次为新增来源小样本验证，尚未重跑全部20组。
