# 规格：Career 自适应备战

- 状态：已完成
- 最后更新：2026-11-17

## 范围

本机单用户按当前目标岗位查看能力画像和下一步计划。复用 v2 SQLite 作答、评价、题库引用和岗位要求。计划是随已保存记录重算的建议，选择训练题、继续追问和确认 Research 补搜都由用户触发。可输入最多四个主题调整范围。

## 数据与规则

- 能力历史增加按主题、具体知识点汇总的画像，保留正确、错误、遗漏、未验证，以及最近可判断的变化。未验证不覆盖上一次有证据的观察。以规范化后的原词匹配，同义名称可能分开列出。
- 计划返回 `practice`、`review`、`followup` 或 `research`。建议带 `reason`、可选薄弱点和带作答编号的依据。未开始时按岗位要求、自评和题库选题。当前对话存在有效追问时可继续，反复出错时提高复习优先级，改善后让其他训练目标优先。在独立作答中持续出现的正确证据用于降低重复优先级。
- 对话沿用最多八轮和随时结束的入口。已经回答或结束的追问不再推荐。题库缺题时只返回岗位和主题供用户确认补搜。推荐本身无外部调用。
- 局部错误保留弱点的题目关联，仅有同主题关联时在理由中明确。旧记录继续用于自评和练习频次。数据库与备份结构沿用现状。

## 接口与状态

- `GET /api/career/ability-history?role=…` 保留原有历史字段，增加 `profile.points`。统计最近 100 条结构化评价，分别返回四类观察次数、最近有据判断、变化方向和作答依据。降低重复优先级需要同一知识点当前连续的正确观察来自至少两次独立练习。明确的「需要再练」自评仍可提高推荐优先级。
- `POST /api/career/plan` 接受当前岗位、可选主题和原有模拟参数。计划带画像。每条建议带原因和依据，复习优先用关联原题，必要时选同主题题。追问建议带 `parent_attempt_id` 和具体问题，补题建议带 `research_request: {role, topics}`。补题时只预填搜索关键词，由用户确认后执行。
- 单题只能继续仍有效且未回答的追问，已保存的请求仍可幂等重试。用户可以随时结束并总结，最多八轮。按已保存的作答刷新计划无需调用 AI，也不会自动切换练习。

## 真实模型验收

全量回归通过 149 项 Node 和 22 项 FastAPI 测试。模拟模型覆盖连续错误、表现改善和旧推荐兼容。

使用官方 `deepseek-flash`、固定合成 RAG 作答和隔离 SQLite。首选原为 SQL 新题。最后一次调用耗时 2.93 秒，保存点评后，最优先建议变为继续 RAG 追问「如果检索返回的片段很多但包含大量无关内容，你会怎样筛选或排序后再交给生成模型？」依据绑定到本轮并定位到原句「检索返回越多，答案就一定越准确」。前一轮验收中，模型未给出可执行追问，首选仍从 SQL 新题切换到复习关联 RAG 原题。隔离 HTTP 服务重启后，画像与计划均相同。

node --env-file=.env scripts/career-eval.mjs --live
