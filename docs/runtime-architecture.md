# 本地工作台的模块职责

更新日期：2026-11-15。本轮保留 Node + SQLite 单体，以及复用该服务的 Electron 桌面入口。

## 前端练习

`public/ui/practice.js` 的 `mountPractice` 持有当前练习的题目关联、草稿、对话、幂等请求标识和请求取消控制器。它通过注入的请求函数访问后端，通过回调通知页面打开资料库及更新备战进度。

页面只使用以下方法，不直接修改内部练习状态：

| 方法 | 用途 |
| --- | --- |
| `sync(state)` | 刷新工作区快照；岗位变化时取消旧请求、恢复对应草稿与对话，同岗位刷新保留当前输入 |
| `flushDraft()` | 等待当前草稿保存；岗位切换和桌面退出前调用 |
| `enter()` | 进入练习页，符合条件时自动推荐一道题 |
| `openQuestion(question)` | 装载推荐题或个人面试题，保留关联信息并确认覆盖未提交回答 |
| `openSourceQuestion(source, question)` | 从资料库选题，核对岗位并关联原题 |

请求取消不意味着服务端一定没有完成保存。对话与本地作答仍使用已有幂等编号；草稿串行保存，不随练习请求一起取消。即使上游忽略取消，原有岗位与对话版本检查仍会拦截过期响应。

`public/app.js` 继续负责页面导航、岗位设置、资料库和搜索。本轮没有迁移前端框架，也没有完成所有页面模块拆分。

## 后端练习

`server.js` 负责访问校验、读取 HTTP 请求、组装依赖和返回响应。`src/practice-api.js` 接收路径、方法、已解析输入和取消信号，集中处理练习接口，调用既有对话、草稿、来源关联和推荐模块，返回状态码与结果。

SQL 和业务规则逐步按所属模块收拢，本轮未引入通用 Repository 或 ORM。搜索、来源编辑和备份入口仍在 `server.js`；推荐算法及外部调用内容保持原有语义。

## 数据库升级

程序启动只通过 `src/database.js` 的 `migrateDatabase(db)` 建立或升级结构：

- 使用 SQLite `user_version` 记录版本；版本 1 接纳原先未版本化的数据库和空数据库。
- 在事务内执行既有建表与补字段逻辑，成功后更新版本；任一步失败则回滚。
- 更高版本数据库拒绝继续启动，避免旧程序误处理新结构。
- 不将旧 `sources.question` 摘要自动提升为用户确认题目。
- JSON 备份仍使用既有 v1 格式；数据库版本不改变备份业务含义。

`questions.js` 和 `workspace.js` 保留初始化函数的兼容导出，供已有隔离测试使用；生产启动不分别调用它们。以后增加结构变更时，应在集中迁移入口新增版本步骤，并验证上一版数据库升级及旧备份恢复。

## 验证与待办

`npm test` 通过 `scripts/test.mjs` 仅发现 `tests/` 中的测试，避免发布源码副本里的测试被重复运行。新增测试覆盖控制器整体挂载、岗位切换、实际事件接线、迁移回滚、备份恢复及练习入口契约。既有部分 UI 测试仍通过截取处理器运行，后续可逐模块改用公开接口测试。

本轮没有调整快速搜索与深度研究之间的依赖方向，也未拆分 `/api/state`；这两项应在对应业务需要变化时再分别推进。
