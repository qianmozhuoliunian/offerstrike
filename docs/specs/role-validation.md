# 规格：确认目标岗位与核心流程约束

- 状态：已完成
- 最后更新：2026-11-11

## 问题与目标

目标岗位决定面经搜索、资料归属和练习上下文。目前任何非空文字都能保存为岗位并用于搜索，搜索结果的关键词筛选不能弥补入口缺少业务判断。目标是先确认用户准备的岗位，再进行后续面试准备。

## 已确认的产品规则

- 目标岗位是职位或岗位方向；明显无关的内容应阻止保存和搜索，如单独的人名、纯数字或乱码。
- 对系统无法判断的名称，说明原因，请用户补充或明确确认；不因为新兴岗位、简称或词库未收录而自动拒绝。
- 结合本地规则与已配置的 AI 服务辅助判断；AI 不可用或输出无效时视为无法判断。发送到 AI 的内容仅为岗位名称，并在操作前告知用户。
- 搜索结果是尚待核实的候选，不能因为包含关键词就断言岗位匹配或属于真实面经；作者自述、博主整理和来源不明的内容应区分。
- 既有岗位、资料和旧备份必须保留；引入新规则后，不能静默删除、改名或覆盖历史记录。

## 本次范围

- 前端与服务端共同约束保存岗位和岗位搜索；无效输入不得作为已确认的目标岗位进入后续搜索。
- 对不确定输入提供继续确认的明确选择，取消时不改动当前岗位；判断失败不得静默视作有效。
- 已保存的旧岗位如尚未经过确认，保留所有数据，并在后续搜索前引导核对；不以岗位名黑名单或有限岗位白名单替代语义判断。
- 扩充端到端验证，检查正常岗位、人名、乱码、简称、新岗位、服务故障、旧数据和备份恢复。

## 已发现的独立规范问题

- 搜索请求只使用已确认岗位要求的前 800 个字符，此前页面和 README 没有说明发送范围；现已按 [搜索数据流规格](search-data-flow.md)处理并验证。
- 当前推荐依据自评和练习时间等规则，并非已经实现基于多次回答内容的完整个性化评估；产品文案和验收应如实表述。

## 验收标准与验证

| 标准 | 验证方式 | 结果 |
| --- | --- | --- |
| 常见岗位、岗位方向和合理的新兴岗位可保存并用于搜索 | 接口和界面测试；真实模型抽样 | 通过：浏览器检查及真实模型抽查产品经理、AI Agent 应用工程师、篮球运动员 |
| 人名、纯数字、乱码等明显无关内容不得保存或发起面经搜索 | 本地规则、模拟模型及真实模型抽样 | 通过：真实模型拦截“科比”，本地规则拦截纯数字和纯符号；其他语义判断依赖模型且可能出错 |
| 判断不确定或服务不可用时需用户补充或确认，取消不改变当前岗位 | 接口和交互测试 | 通过：模拟服务故障、无效输出和浏览器取消与确认；真实模型将“AI”判为待确认 |
| 绕过页面直接调用搜索也不能使用未经确认的目标岗位 | 接口测试 | 通过：未核对的旧岗位与非当前岗位均不能发起搜索 |
| 旧岗位及其资料不丢失，旧备份仍可恢复；旧岗位重新核对后可搜索 | 隔离数据和旧备份恢复测试 | 通过：旧备份和新导出均在隔离数据库恢复，原岗位描述与草稿保留 |
| 岗位验证只向配置的 AI 发送岗位名称，失败和数据流向有明确提示 | 模拟外部服务与页面检查 | 通过：模拟服务检查请求体，浏览器检查告知和确认流程 |

## 数据与外部服务影响

岗位验证可能把用户输入的岗位名称发送给已配置的 AI 服务；不发送简历、岗位描述、回答或历史记录。继续使用既有本地数据库与备份格式，已保存数据不会因本次校验被清除。

## 验证记录与限制

- 2026-11-11：完整自动化测试 70 项通过，包含竞态、取消确认、模型故障和旧备份恢复；隔离浏览器检查旧岗位、无关内容、正常岗位及不确定输入。
- 真实 AI 抽查仅覆盖少量示例，模型可能误判或无法判断；AI 不可用时，系统会请求用户自行确认，不能保证自动识别所有无关输入。核对状态仅作为当前本地缓存，不写入备份；从备份恢复的岗位需重新核对，资料不受影响。
