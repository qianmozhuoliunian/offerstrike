# InterviewRadar 参考与实施顺序

核对日期：2026-11-13。资料来自 [InterviewRadar 仓库](https://github.com/KunChen1110/InterviewRadar)及其 [工作流](https://github.com/KunChen1110/InterviewRadar/blob/main/SKILL.md)，没有运行竞品或验证实际抓取覆盖率。仓库以 Agent 工作流和 Markdown 备考包为主；视觉方向由用户选择参考 GitHub 仓库页面，并非声称该项目有独立 Web 界面。

| 参考点 | 对方公开的实现或要求 | 本项目现状和下一步 |
| --- | --- | --- |
| 原文证据 | 先发现 URL、读取内容、切分候选，再校验摘录及来源；无法核对的内容被拒绝 | 已支持粘贴原文、提取候选并确认保存依据；本次改为逐题审核。粘贴内容不代表原帖已核实 |
| 来源和缺口 | 工作流要求披露来源降级、日期不明和 OCR 未覆盖；小红书另依赖登录和采集工具 | 现有搜索使用 Tavily 的公开结果，是否能读取正文需另行验证；优先改善来源状态和失败提示，不宣称平台站内已接入 |
| 独立来源与高频 | 规范要求至少两个独立来源支持才能称高频，并区分单来源 | 可考虑在已确认题目上展示独立来源数；需先解决不同问法语义合并与误合并的验证，不以摘要重复冒充高频 |
| 备考包 | 包含来源概况、题目依据、回答框架和阶段计划；简历关联追问需双重依据 | 可先设计基于已确认题目的岗位备考清单，再评估输出形式；简历数据须独立授权，不能默认读取复习记录或虚构经历 |
| 视觉 | 用户选择参考 GitHub 仓库页面的层级、边框、引用块与信息密度 | 本次仅在逐题审核组件尝试；其他页面先逐步检验，保留现有品牌与可访问性 |

推荐顺序：先完善来源状态与可核查的题目整理，再用真实岗位样本验证来源与相关性；接着设计独立来源统计和可执行的备考清单。简历关联、平台正文读取和相似题合并均需单独明确数据处理、失败条件及验收，不因竞品具备而视为已实现。
