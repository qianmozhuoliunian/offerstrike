# 轻量规格工作流

规格用于在动手前讲清楚问题、改动范围和完成标准，让用户和执行者对同一件事有共同预期。产品定位和已确认的长期决策以 [DESIGN.md](../../DESIGN.md) 为准。

## 什么时候写

新功能、跨模块调整，以及影响用户数据、外部服务或核心流程的改动，在实现前使用 [模板](TEMPLATE.md) 创建规格。单纯的文案、格式调整和范围明确的小修复，可直接修改并按风险验证。用户明确要求直接处理时，遵循用户要求，必要时在执行中简要记录范围与结果。

## 如何使用

1. 阅读相关设计、实现和已有规格，描述实际问题；将已确认的需求、假设和待决定事项分开。需要用户决定且会实质影响范围或风险的问题，提出问题并继续不依赖答案的工作。
2. 复制模板，以简短的功能名命名文件，填写目标、范围、验收标准及验证方法。规格记录待验证的行为，不把假设写成已实现事实。
3. 按规格检查实现和数据影响，拆成可验证的小步骤。范围变化时同步更新规格；涉及产品决策变化时更新 DESIGN.md。
4. 对照每条验收标准记录验证结果，说明未验证内容与限制；完成后更新状态。相关后续工作另行记录，不把未完成事项标为完成。

规格不要求每个字段都写长篇内容；不适用时写“不适用”即可。规格是工作记录，不代替代码、测试或用户的明确指示。

## 状态

- **草稿**：问题、范围或验收方式仍待梳理。
- **进行中**：范围足以开展工作，尚有实现或验证未完成。
- **已完成**：范围内工作和验收已完成，结果与限制已记录。
- **暂停**：工作暂时停止，并记录原因及恢复条件。
