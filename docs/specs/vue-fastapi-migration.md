用户已确认逐个功能迁移整个项目。现有工作台由 public 页面、Node server.js、src 业务模块和 SQLite 组成，research_service 是独立检索适配器。桌面入口通过 Electron 启动 Node，公开 demo 使用独立示例数据。

## 第一批文件与接口

- backend/database.py 与 schema.sql 管理同版本数据库初始化及旧表兼容。
- backend/app.py 提供岗位、岗位要求、来源、题目、主题、笔记、日期接口及本机访问保护。
- backend/run.py 加载根目录 .env，生成临时访问凭证，启动本机服务。
- frontend/src 下的 Vue 组件提供岗位与资料库工作流。frontend 的构建输出到忽略的 dist/vue。
- backend/tests 通过真实 SQLite 和 HTTP API 验证读写、回滚、重启、证据与 Node 双向兼容。
- 根 package.json 增加明确的新版构建与启动命令。

GET /api/workspace 返回当前岗位、确认状态、岗位要求及含关联题目与证据的收藏来源。岗位及资料库修改沿用原有路径和字段。尚未迁移的业务仍由现有工作台入口承担。

岗位语义识别在后续 AI 服务迁移时接入。第一批采用显式人工确认，未知岗位保持待确认状态，确认令牌绑定岗位、旧岗位和请求顺序，五分钟过期。

先通过回答证据、遗漏与未验证的 API 回归样本，再验证重复提交、并行追问、岗位切换、模型失败、重启读取与旧数据兼容。至少一次真实模型练习单独记录，正常保存的评价供第四批 Career 读取。

第三批已有 6 项练习 API 验证通过，覆盖基于回答的证据、遗漏要求、结构化失效降级、8 轮停止、并发幂等、草稿、离线、自评、总结及重启读取。页面流程通过真实 FastAPI、临时 SQLite 与模拟外部模型，已覆盖搜索确认后的题目练习、能力观察展示和本题总结。

真实 deepseek-flash 测试使用同一合成 RAG 回答与隔离数据库，共调用 4 次。前两次分别缺少顶层点评字段和 JSON 格式不合法，HTTP 400、未保存成功练习。第三次 HTTP 200，保留点评，结构化观察因 unverified 超过 4 项降级为 null。调整提示词为单个完整 JSON 结构并要求更精简的观察后，第四次 HTTP 200，结构化评价通过，保存 1 条练习及评价，用时 2899ms，模型报告输入 673 tokens、输出 360 tokens。追问目标不合规，因此保留观察并将行动转为 review。四次合计输入 2378 tokens、输出 1928 tokens，实际费用待账单核对。上述结果验证格式、证据定位与保存链路，评价内容的业务准确性仍需按人工样本持续核验。
