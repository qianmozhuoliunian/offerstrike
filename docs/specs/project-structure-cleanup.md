# 规格：项目结构梳理与冗余清理

- 状态：已完成
- 最后更新：2026-11-11

## 问题与目标

现有功能逐步增加，前端页面逻辑集中在一个文件中，也存在旧界面遗留的实现。梳理项目职责并清理有证据表明不再使用的代码，方便之后定位和维护，同时保持现有使用体验。

## 已确认、假设与待决定

- 已确认：用户希望理顺项目结构、检查冗余并删除确认无用的代码。
- 假设：保留现有产品功能、数据格式及运行方式；不为了拆分文件而大规模重写。
- 待决定：更大范围的前端业务拆分需要结合后续功能变更和依赖分析逐步进行。

## 本次范围

- 梳理目录、入口与主要模块职责，补充项目结构说明。
- 检查实际引用与动态生成的界面，清理能够确认没有使用的代码。
- 将职责独立、依赖清晰的提示通知逻辑从前端入口中分离。
- 将通用日期校验从工作台逻辑中移出，并把本机请求校验与外部服务数据处理分开。
- 检查静态资源加载、核心行为和现有自动化测试。

## 本次不做

- 不新增产品功能、改变数据结构、删除用户资料或修改外部服务配置。
- 不因文件较大就删除代码；不将历史数据兼容逻辑当作冗余。
- 不清理用户工作数据、个人文件、历史记录和用途不明的文件。
