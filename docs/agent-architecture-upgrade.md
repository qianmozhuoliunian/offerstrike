# OfferPilot AI：Agent 架构升级方案

阶段 0 · 2026-11-13 · 审查基线 `6a97a58`。下文的仓库现状描述该基线；此后实现和验收进展见 [Agent 使用与验收](agent-evaluation.md)。

## 仓库实际状态

项目当前是单用户本地工作台。原生 HTML/CSS/JS 页面由 Node 的 `node:http` 同源提供，Node 22.13+ 可运行，使用内置 `node:sqlite`，无 npm 第三方运行依赖。服务只监听本机，默认从 8080 尝试端口。当前没有多人账号、生产部署或持续集成配置。FastAPI 是可选的第二个本机进程，不拥有数据库。

| 现有能力 | 代码依据与可复用部分 | 与目标的差距 |
| --- | --- | --- |
| 岗位与 JD | [server.js](../server.js) 的岗位确认和 JD 提取；[services.js](../src/services.js) 校验提取结果能否对应原文；[workspace.js](../src/workspace.js) 保存用户确认的要求 | 搜索有意不发送 JD 或岗位要求。研究模式应让用户选择可公开的主题词，预览实际发出的内容 |
| 多源检索 | [interview-research.js](../src/interview-research.js) 调用 Tavily 两路固定查询；不足 3 条初筛线索时按配置补一次 Exa。复用域名、日期、URL 去重、结果分组及可选的 [AI 相关性判断](../src/search-ai-relevance.js) | 停止条件依据标题线索。没有主题覆盖评估、原帖读取、按缺口调整查询或统一任务预算 |
| Python 检索 | [FastAPI 接口](../research_service/main.py) 执行一轮指定供应商请求；[Node 适配器](../src/fastapi-retrieval.js) 通过本机 HTTP 调用，由 `RESEARCH_SERVICE_URL` 开启 | 它是检索适配器，补搜和质量判断在 Node。两端都有供应商请求映射，继续复制规划和证据规则会增加维护成本 |
| 题库与证据 | [source-extraction.js](../src/source-extraction.js) 校验粘贴文本和逐字摘录；[questions.js](../src/questions.js) 保存用户确认的题干和证据，保留来源、主题及稳定编号 | 摘要、用户提供的文字和成功读取的原帖必须区分；抽取结果的原题/主题整理标签及日期依据尚未完整建模 |
| 练习与复习 | [dialogue.js](../src/dialogue.js) 实现单题多轮追问、总结、重试和恢复；[recommendation.js](../src/recommendation.js) 依据作答和自评推荐、解释原因 | 目前没有多题模拟面试会话、独立简历分析、跨主题能力画像或备战计划。不要把单题点评当作技能评分 |
| 持久化与回滚 | SQLite：`settings`、`job_profiles`；`sources`、`questions`、`question_topics`、`question_evidence`；`attempts`、自评、题目关联及对话详情、草稿、总结、面试复盘。由 [server.js](../server.js)、[questions.js](../src/questions.js)、[workspace.js](../src/workspace.js) 建表；[import-data.js](../src/import-data.js) 支持旧 v1 备份预览及事务合并 | Research MVP 不需要新表。将来需要持久化新来源元数据或备战计划时，再做可兼容旧库和旧备份的增量迁移 |

当前可用主线是搜索 → 收藏来源 → 粘贴原文或手动整理 → 核对入库 → 单题练习 → 自评和推荐。[搜索页](../public/app.js) 已处理切岗位、过期结果和取消请求，接入时要继续保护这些行为。现有 `skills/` 是界面动画工作说明，未参与面经运行。

## 建议架构

```text
现有 Web 页面 → Node HTTP 入口
                  ├─ 原搜索与原有业务接口（兼容入口）
                  ├─ 深度研究入口 → Research 模块 → 检索 / 原文读取 / AI 提取
                  │                        ↑
                  └─ Career 模块（后续）────┘ → 复用题库、练习、推荐
                        │
                        └─ Node 管理已确认数据和备战进度 → SQLite
```

- **Research** 提供一个小接口：`research({ role, company, scope, topics }, { signal })`。输入是确认后的岗位和用户选定的主题、平台及时间条件，输出是来源、候选题、覆盖缺口、停止原因和使用量。内部注入两家检索适配器、可替换的读取工具和模型调用。调用方无需理解每家供应商的字段，也不必自己拼接搜索、读取和筛选步骤。原始 JD 走现有提取与确认流程；预览并确认后只把选定的公开关键词送给搜索服务。
- **Career** 提供下一步建议：优先查同岗位题库，依据已确认的 JD 要求、稳定题目编号、练习和自评安排任务；缺资料时建议用户启动 Research，只传选定的主题。后续确有多步规划需求时，可让模型从「练习、换主题、补搜」等有限动作中提出建议，由代码校验及执行。数据库查询、入库、授权、证据判定条件和预算扣减仍是普通代码。
- **Skills** 是可检查的工作指令。建议在 `src/research/skills/` 按固定名称加载，仅在对应步骤需要时读入：`search-strategy` 规定如何用公开主题覆盖搜索缺口；`interview-extraction` 定义证据和题型输出；`source-verification` 定义原文及证据核对规则；`quality-evaluation` 定义如何区分线索、整理和可确认候选。检索、读页、逐字匹配及去重由代码执行。不要动态执行文档或网页内容；先有真实调用方，再添加对应文件。

建议目录按实际改动渐进形成，既有路径在迁移期保留：

```text
server.js                    路由、岗位校验、应用配置
public/                      现有页面；后续加可选深度研究和候选核对
src/
  interview-research.js      现有快速搜索，保留为基线和回退
  research/
    index.js                 研究接口，内部控制轮次和停止条件
    providers.js             Tavily / Exa，复用现有请求映射
    read-source.js           经验证来源的正文读取
    skills/                  随实际步骤加入运行时指令
  source-extraction.js       共用候选结构和证据校验
  career/                    阶段 3 才创建
  dialogue.js / questions.js / workspace.js / recommendation.js
research_service/            可选 FastAPI 检索适配器
tests/                       接口、受控失败、评估样本
```

**技术选型：本轮在 Node 完成 Research MVP。** 保留已经验证的 FastAPI 可选模式，不拆新的服务。当前 FastAPI 只接受固定检索词，不能直接承载动态主题；先让研究接口独立于传输，日后确需 Python 专用读取能力、独立部署或想用 Python 实现研究流程时，再按同一契约替换。两条路径共用产品规则，避免同时维护两个规划器。当前预算和暂停点可由普通 JS 表达；出现长任务跨重启恢复或多次人工暂停需求时，再评估 LangGraph。

## 研究结果与预算

研究先用岗位、公司和选定主题查询，读取少量合规可访问的公开原帖，再按**有证据的题目及主题覆盖**决定补哪一块。仅有摘要、登录墙、来源不可读或无明确提问时，可展示待核实链接，不计入证据产出。读取只接受检索结果中的已验证来源，限制重定向、响应大小、时间与文本范围；登录、验证码或平台禁止自动读取时回到手动粘贴。正文是待分析材料，不可指挥工具，也不直接写入数据库。

每条候选题保留题干、逐字摘录、原始链接、证据来自读到的正文还是用户粘贴文本、题目类型和主题；公司、岗位和发布时间单列其依据，无法确定则留空。明确记载的题、由原文主题整理的题和 AI 练习题分开。MVP 先交付前一种；逐字命中只说明摘录存在，用户仍要核对摘录是否支持题干，作者自述不等于独立证实。去重不能丢失另一原帖中的出处。

建议的 MVP 上限（待样本验证）：**2 轮、4 次搜索、2 次读取、3 次模型调用、75 秒总时限**。先按规则选题和补缺口，模型主要做提取；需要规划模型时也占这 3 次。建议每次模型输入按实际送出范围设字符上限，配置输出 token 上限，按供应商返回记录用量；待选模型确定后再设置任务的 token 和金额上限，并在发请求前预留预算。无价格或用量信息时标为未知，不能写成零。满足最低证据目标、已无新主题/链接、预算用尽、用户取消或到期即停止，返回已有结果和具体原因。每次记录供应商、成功/失败、耗时、调用次数和用量，不默认记原始 JD、简历、正文或密钥。

可验证的决策例子：用户选了 RAG 和工具调用，首轮只有 RAG 的原帖证据。第二轮只补工具调用；如果两个主题都已有至少一条通过结构与证据检查的候选，或读取预算已用完，就停止，不因总结果数少而继续盲搜。证据候选和人工确认结果分别统计。

## 迁移顺序与验收

| 阶段 | 任务与依赖 | 验收 |
| --- | --- | --- |
| 0 · 仓库审查 | 核对代码、现行规范、备份与测试，记录真实服务验证边界 | 本文；重新跑 Node 111 项、FastAPI 14 项测试通过。Python 测试有一条 TestClient 依赖弃用提示 |
| 1A · 证据链 | 在动手前补实现规格。从一个允许读取且能稳定提取正文的站点验证；先做「检索候选 → 读取 → 调用共用抽取 → 核对证据」，做独立可调用入口；无合适来源时保留手动输入，记作读取门槛未通过 | 受控样本覆盖正常正文、只有摘要、无提问、错误摘录和读取失败。用真实公开岗位/JD 选出至少一个可公开主题；人工核对至少一条成功读取的真实原帖及候选证据，确认没有自动入库 |
| 1B · 研究循环 | 在 1A 上统一供应商契约；按确认的主题补缺口；接入全任务预算和记录。实测第二家供应商需要独立凭据 | 证明同一真实任务可以按缺口调整，最终给出带证据的结构化结果；两家均至少真实调用成功一次，故障切换及限额用受控测试复现；没配置第二家时只能通过单源部分 |
| 2 · Web 接入 | 先在原搜索页加可选研究模式，关闭时继续使用现有 `POST /api/search`。核对结果复用现有收藏和题库确认流程；需新元数据时用增量字段和兼容备份 | 浏览器验证搜索、候选核对、确认入库、从该题开始练习；失败仍可快速搜或手动添加；切换岗位不串资料。若涉及数据字段，用隔离副本验证旧库、旧备份、重复确认及关闭新模式回退 |
| 3 · Career | 依赖 Research 已验证和已确认题库。先用 JD 与自评做「查题 → 练习 → 调整任务」，简历能力提取和多题模拟分开补齐 | 同一岗位用两种自评得到可解释的不同后续任务；无题提示选择补搜，未评估不视为薄弱；无简历也可运行，简历仅按用户明确选择参与 |
| 4 · 工程化 | 从阶段 1 就采集必要用量；稳定后补短期公开结果缓存、限额内重试和评估文档。缓存按服务、查询和筛选范围区分，不跨用户复用私有内容 | 复用[既定 20 项任务](interview-research-roadmap.md#对比任务与判定)，同条件比较 Tavily 基线、当前多源搜索和 Research MVP。人工核对有证据有效题数、岗位相关度、错误来源比例，同时记录延迟、调用和实计费用；失败与不可访问保留在样本中 |

配置回退分两层：Web 可关闭研究模式回到现有搜索；检索端可清除 `RESEARCH_SERVICE_URL` 并重启回到 Node 直连。超时后不偷偷再执行一轮，以免重复计费。阶段 1 不碰现有资料和备份；读页结果在确认前只用于本次任务。

**当前验收边界：** [已有规格](specs/fastapi-research-adapter.md) 记录了 FastAPI 对 Tavily 的真实调用及模拟双进程联调。本机只发现 Tavily 搜索配置，Exa 仍只有模拟覆盖，20 项实测和原帖可读性均未完成。下一次实现从 1A 开始；它可用 Tavily 与受控样本推进，不必为等第二家密钥推迟验证证据链。
